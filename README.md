# Titanic Survival Classification Pipeline

An end-to-end, reproducible classification pipeline that predicts Titanic
passenger survival.  The final submitted model is a **PyTorch tabular
embedding MLP** (`TitanicEmbeddingMLP`).  Classical ML models (Logistic
Regression, Random Forest, Gradient Boosting) are included as
**sanity-check baselines only** — they are never used for inference.

The pipeline is designed to be:
- **Leakage-free** — all learned statistics (vocabulary mappings, imputer
  medians, scaler parameters) are fitted on the training split only.
- **Reproducible** — a single seed controls Python, NumPy, and PyTorch.
- **GitHub-ready** — raw data and generated artifacts are git-ignored; only
  code and the synthetic demo sample are committed.

## Setup

### 1. Clone and install

```bash
git clone <your-repo-url>
cd titanic-survival-pipeline
python -m venv .venv

# Linux / macOS
source .venv/bin/activate

# Windows
.venv\Scripts\activate

pip install -r requirements.txt
```

The pipeline is **CPU-only**; no GPU is required.

### 2. Kaggle API credentials

The training script downloads the Titanic dataset automatically via the
Kaggle API.

1. Go to **kaggle.com → Account → Settings → API → Create New Token**.
   This downloads `kaggle.json`.
2. Place the file in the OS-appropriate location:

   | OS | Path |
   |---|---|
   | Linux / macOS | `~/.kaggle/kaggle.json`  (run `chmod 600` to restrict permissions) |
   | Windows | `C:\Users\<YOUR_USER>\.kaggle\kaggle.json` |

   Alternatively, set environment variables:
   ```bash
   # Linux / macOS
   export KAGGLE_USERNAME=your_username
   export KAGGLE_KEY=your_key

   # Windows
   set KAGGLE_USERNAME=your_username
   set KAGGLE_KEY=your_key
   ```

3. **Join the competition and accept its rules** at
   <https://www.kaggle.com/competitions/titanic/rules>.
   Downloads fail without this step.

> **No Kaggle access?**  Use `--use-sample` to train on the bundled
> synthetic dataset.  Metrics from that run are illustrative only — they
> are not from the real Titanic data.

## Usage

### Train on the real Kaggle data

```bash
python train.py
```

### Train on the bundled synthetic demo (no credentials needed)

```bash
python train.py --use-sample
```

### Skip classical baseline training (faster on slow machines)

```bash
python train.py --skip-baselines
```

### Override hyperparameters

```bash
python train.py --epochs 200 --lr 5e-4 --hidden-dims 128 64 32 --dropout 0.2
```

Training steps:
1. Load `data/raw/train.csv` (or the sample).
2. Engineer features — all row-wise, no dataset-level statistics before the split.
3. Stratified train / validation / test split (defaults: 70 / 15 / 15 %).
4. Fit `TabularPreprocessor` on the **train split only**.
5. Train `TitanicEmbeddingMLP` with Adam + early stopping on validation loss.
6. Auto-tune decision threshold on the **validation split** (maximises F1).
7. Evaluate once on the **held-out test split**.
8. Train classical ML baselines for comparison (unless `--skip-baselines`).
9. Save all artifacts to `artifacts/` and plots to `reports/`.

> **Important:** The Kaggle `test.csv` has no `Survived` label and is
> **never used for evaluation**.  All reported metrics come from the
> held-out portion of Kaggle `train.csv`.

### CLI options

| Flag | Default | Description |
|---|---|---|
| `--use-sample` | off | Train on the bundled synthetic sample |
| `--no-download` | off | Require local `data/raw/train.csv`; do not download |
| `--skip-baselines` | off | Skip LR / RF / GB training |
| `--epochs` | 100 | Maximum training epochs |
| `--batch-size` | 32 | Mini-batch size |
| `--lr` | 0.001 | Adam learning rate |
| `--weight-decay` | 0.0001 | L2 regularisation coefficient |
| `--dropout` | 0.3 | Dropout probability |
| `--hidden-dims` | 64 32 | MLP hidden layer widths |
| `--patience` | 15 | Early-stopping patience (epochs without val improvement) |
| `--test-size` | 0.15 | Held-out test fraction |
| `--val-size` | 0.15 | Validation fraction |
| `--threshold` | auto | Decision threshold override; omit to auto-tune on val F1 |
| `--seed` | 42 | Random seed |

### Launch the Streamlit app

```bash
streamlit run ds_app.py
```

**"Training results" tab** — test metrics, classification report, model
comparison table (PyTorch vs baselines), confusion matrix, ROC curve, and
training curves.

**"Run inference" tab** — upload a CSV or enter a file path, run
`TitanicEmbeddingMLP` predictions, download results.  If the CSV contains a
`Survived` column, evaluation metrics and plots are shown; if not (e.g. the
Kaggle `test.csv`), only predictions and probabilities are shown.

## Architecture & design choices

### Model — `TitanicEmbeddingMLP`

A PyTorch tabular embedding MLP:

```
[Pclass]         → Embedding(vocab, dim)  ┐
[Sex]            → Embedding(vocab, dim)  │
[Embarked]       → Embedding(vocab, dim)  ├─ concat ─► Linear → LayerNorm → ReLU → Dropout
[Title]          → Embedding(vocab, dim)  │            (× len(hidden_dims))
[Deck]           → Embedding(vocab, dim)  │                      │
[FamilySizeGroup]→ Embedding(vocab, dim)  ┘                      ▼
[Age, LogFare, SibSp, Parch, FamilySize,                    single logit
 IsAlone, HasCabin, AgeMissing, FareMissing] (imputed + z-scored)
```

Key choices:
- **Categorical embeddings** learn compact, task-specific vector
  representations for categorical variables, rather than representing each
  category as an independent sparse one-hot indicator.
- **Embedding dim rule**: `min(50, max(2, (vocab_size + 1) // 2))` —
  conservative on a small dataset (~620 training rows).
- **LayerNorm** instead of BatchNorm — works correctly with any batch size,
  including batch size 1 during inference.
- **BCEWithLogitsLoss** — numerically stable binary cross-entropy; sigmoid
  is applied at inference time only.

### Feature engineering (row-wise, leakage-free)

All features are computed per row before the split; no group statistics,
frequency encoding, or quantile fitting are used:

| Feature | Derivation |
|---|---|
| `Title` | Extracted from `Name`; normalised to Mr / Miss / Mrs / Master / Rare |
| `FamilySize` | `SibSp + Parch + 1` |
| `IsAlone` | `1` if `FamilySize == 1` |
| `FamilySizeGroup` | Fixed bins: Alone (1) / Small (2–4) / Large (5+) |
| `HasCabin` | `1` if `Cabin` is non-missing and non-empty |
| `Deck` | First letter of `Cabin`; `Unknown` if missing |
| `LogFare` | `log1p(Fare)`; `NaN` stays `NaN` for the imputer |
| `AgeMissing` | `1` if `Age` is `NaN` (computed before imputation) |
| `FareMissing` | `1` if `Fare` is `NaN` (computed before imputation) |

### Preprocessing — two separate paths

The PyTorch model and the classical baselines use different preprocessing
strategies suited to their respective architectures:

| Path | Used for | Categorical | Continuous |
|---|---|---|---|
| `TabularPreprocessor` | PyTorch model only | Custom vocab mapping → `nn.Embedding` | Median imputation → StandardScaler |
| `ColumnTransformer` | Classical baselines only | `OneHotEncoder(handle_unknown='ignore')` | Median imputation → StandardScaler |

Both are fitted on the training split only.

### Classical ML baselines

Logistic Regression, Random Forest, and Gradient Boosting are trained on
the same engineered features as the PyTorch model, but with
model-appropriate preprocessing: one-hot encoding for categorical variables
and numeric imputation/scaling for continuous variables.

Each model is selected via **5-fold stratified cross-validated grid search
on the training split only**, then evaluated once on the held-out test
split.  Results are saved to `artifacts/baseline_metrics.json` and
displayed in the Streamlit comparison table.  **Baselines are never used
for inference.**

## Troubleshooting

**Kaggle credentials not found**
```
Kaggle authentication failed.
```
Place `kaggle.json` in the correct OS path (see *Setup → Kaggle API
credentials* above) or set `KAGGLE_USERNAME` / `KAGGLE_KEY` environment
variables.

---

**Competition rules not accepted**
```
Failed to download the Titanic data.
```
Visit <https://www.kaggle.com/competitions/titanic/rules>, log in, and
accept the competition rules.  Then retry.

---

**No artifacts found (Streamlit app)**
```
Required artifact 'metadata.json' not found.
```
Run `python train.py` first to generate all artifacts under `artifacts/`.

---

**Kaggle `test.csv` has no labels**

The `test.csv` file from Kaggle does not contain a `Survived` column.
When you upload it in the inference tab, the app shows predictions and
probabilities only — evaluation metrics are not available without
ground-truth labels.  This is expected behaviour.

---

**Synthetic sample metrics are illustrative only**

When training with `--use-sample`, the app shows a banner:
*"These metrics are from the SYNTHETIC SAMPLE dataset."*
The synthetic CSV is schema-faithful but not the real Titanic data.
Always quote metrics from a run on the real Kaggle `train.csv`.

## Evaluation notes

- All evaluation uses the stratified held-out test portion of Kaggle
  `train.csv`.  With a 15 % test fraction (~134 rows), reported metrics
  carry meaningful variance; k-fold cross-validation would tighten
  estimates but is outside the one-day scope.
- The decision threshold is auto-tuned on the validation split to maximise
  F1 (override with `--threshold`).
- The pipeline is CPU-only; `torch>=2.1` (CPU build) is sufficient.
