# 🚢 Titanic Survival Prediction — End-to-End Classification Pipeline

A reproducible, end-to-end pipeline that predicts Titanic passenger survival with a
**PyTorch** neural network. It covers data fetching, EDA, leakage-free preprocessing,
training in a standalone script, held-out evaluation, and a **Streamlit** app for
inspecting results and running inference on new CSVs.

> **Why these choices?** The Kaggle `test.csv` has **no `Survived` label**, so it cannot
> be used for evaluation. All modelling therefore uses Kaggle `train.csv`, which is split
> with a **stratified** train/validation/test split. Preprocessing objects are fit on the
> **training split only** to avoid data leakage.

## Setup

### 1. Clone & install

```bash
git clone <your-repo-url>
cd titanic-survival-pipeline
python -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt
```

The pipeline is **CPU-only**; no GPU is required.

### 2. Kaggle API setup (to fetch the real dataset)

1. Create a Kaggle account and go to **Account → Settings → API → "Create New Token"**.
   This downloads `kaggle.json`.
2. Place it where the Kaggle client looks for it and lock down permissions:

   ```bash
   mkdir -p ~/.kaggle
   mv ~/Downloads/kaggle.json ~/.kaggle/kaggle.json
   chmod 600 ~/.kaggle/kaggle.json
   ```

   Alternatively, set environment variables:

   ```bash
   export KAGGLE_USERNAME=your_username
   export KAGGLE_KEY=your_key
   ```

3. **Join the competition and accept its rules** at
   <https://www.kaggle.com/competitions/titanic/rules> — downloads fail otherwise.

> **No Kaggle access?** Everything still runs against the bundled synthetic sample via
> `--use-sample`. The sample is schema-faithful but **not** the real data, so its metrics
> are illustrative only.

## Usage

### Train

```bash
python train.py                 # fetch from Kaggle (falls back to sample on failure)
python train.py --use-sample    # force the bundled synthetic demo dataset
python train.py --epochs 200 --lr 5e-4 --hidden-dims 128 64 32   # override defaults
```

Training will:
1. set seeds,
2. load `train.csv` (or the sample),
3. engineer features,
4. make a stratified train/val/test split,
5. fit the preprocessor on **train only** and transform all splits,
6. train the MLP with early stopping,
7. evaluate on the held-out **test** split, and
8. save `artifacts/{model.pt, preprocessor.joblib, metadata.json, metrics.json}` plus
   plots in `reports/`.

### Launch the Streamlit app

```bash
streamlit run ds_app.py
```

- **Training results** tab — metrics, classification report, confusion matrix, ROC curve,
  and training curves saved by `train.py`.
- **Run inference** tab — upload a CSV or enter a path, run predictions, and **download**
  the results. If the CSV contains a `Survived` column, evaluation metrics and plots are
  shown; if not (e.g. the Kaggle `test.csv`), predictions and probabilities are shown.

#### Example usage

```bash
# 1. train on the real data
python train.py
# 2. open the app, go to "Run inference", and either upload a CSV
#    or enter a path such as:  data/raw/test.csv
streamlit run ds_app.py
```

## Architecture & design choices

**Model.** A compact PyTorch MLP (`Linear → BatchNorm → ReLU → Dropout` blocks, default
hidden widths `[64, 32]`) outputting a single **logit**, trained with
`BCEWithLogitsLoss` (numerically stable vs. a separate sigmoid + BCE) and Adam with weight
decay. BatchNorm + dropout regularise a small, tabular dataset; early stopping on
validation loss prevents overfitting and restores the best weights.

**Feature engineering (leakage-free).** `Title` (from `Name`), `Deck` (from `Cabin`),
`FamilySize` and `IsAlone` are computed **row-wise**, so they can be applied identically to
train, validation, test, and inference data without leaking information across rows.

**Preprocessing (`ColumnTransformer`).**
- Numeric (`Age, Fare, SibSp, Parch, FamilySize, IsAlone`): median imputation → standard
  scaling (an MLP benefits from standardised inputs).
- Categorical (`Pclass, Sex, Embarked, Title, Deck`): most-frequent imputation →
  one-hot encoding with `handle_unknown='ignore'`, so unseen categories at inference do
  not crash the pipeline.
- The transformer is **fit on the training split only**, then reused everywhere.

**Reproducibility.** A single seed (`config.RANDOM_SEED = 42`) covers Python, NumPy, and
PyTorch, plus stratified splits. Every artifact needed to reproduce a prediction is saved:
weights (`model.pt`), the fitted preprocessor (`preprocessor.joblib`), and
`metadata.json` (input dimension, architecture, threshold, feature lists, output feature
names, seed, timestamp). Inference rebuilds the exact model from metadata.

**Evaluation strategy.** Because the Kaggle `test.csv` is unlabelled, the labelled
`train.csv` is split **stratified** into train/validation/test (defaults 70/15/15).
Validation drives early stopping; the **test** split is touched only once for the final,
unbiased estimate. Reported metrics: accuracy, precision, recall, F1, ROC-AUC, confusion
matrix, and the full classification report — appropriate for an imbalanced target.

**Robustness / error handling.** Clear, actionable errors for missing Kaggle credentials
or unaccepted competition rules; missing artifact files; empty/malformed CSVs; and missing
or partial columns (engineered features degrade gracefully to `Unknown`/`NaN` + imputation).

## Evaluation notes & limitations

- **Synthetic sample.** `data/sample/sample_titanic.csv` is generated by
  `scripts/generate_sample.py` and is **not** the real Titanic data. Use it only to verify
  the plumbing; quote metrics from a run on the real Kaggle data.
- **Small test set.** With ~890 labelled rows, a 15% test split is ~130 rows, so metrics
  carry meaningful variance. For a one-day scope this is an accepted trade-off; k-fold
  cross-validation would tighten estimates.
- **Threshold.** A 0.5 decision threshold is the default; it can be tuned on the validation
  split if precision/recall need balancing.
- **Model ceiling.** An MLP on these tabular features typically lands around ~80–83%
  accuracy — competitive but not dramatically better than strong tree baselines. The point
  of this assignment is a clean, reproducible **pipeline**, not leaderboard chasing.
